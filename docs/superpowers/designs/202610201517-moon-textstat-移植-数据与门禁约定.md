## 1. AD-1 字典数据身份约定

### 1.1 数据分层

本设计把数据分成三层，三层的身份分别固定，避免「只锁产物、不锁输入」导致 oracle 不可复现。

| 层 | 位置 | 是否进发布包 | 说明 |
| --- | --- | --- | --- |
| L1 上游输入 | 仓库内 `vendor/upstream/`（**模块根之外**） | 否 | Pyphen 断字模式文件、CMUdict 语料文件、上游易读词表。是切片与生成的唯一输入 |
| L2 生成产物 | 模块内 `data/`（MoonBit 包） | 是 | 由 L1 经生成步骤得到的源码内嵌表（字符串字面量） |
| L3 oracle 期望值 | 模块内 `gate/data/`（MoonBit 包） | 是 | 由 `docs/facts/oracle_smoke.json` 经生成步骤得到的期望值源码表 |

L1 位于模块根之外这一位置不是随意的：`moon package` 会把模块目录内所有**未被忽略**的文件打进发布包（`docs/facts/moonbit-embedding-and-naming-probe.md` §2：`data/`、`_data/`、`internal/` 均被打进 zip，被 `.gitignore` 命中的 `notes/` 与 `gen/` 未被扫入；同一探测中一个误放的 26 MB `nodereal/node.exe` 也被打进 zip）。`moon.mod` **没有** `files` 键（同报告 §2，报错逐字为 `Unexpected key 'files' found in moon.mod.`，EXIT=255），所以包内容无法用清单收窄，唯一可用的隔离手段是「放进模块目录之外」。嵌套布局实测（本设计期间执行，一次性目录已删除）：

```console
$ cd /f/Temp/nested/repo && ls
docs  lib  textstat
$ cd lib && moon package        # lib 是模块根，docs/ 与 textstat/ 在其外
$ python -c "import zipfile,glob; z=sorted(glob.glob('_build/publish/*.zip'))[-1]; print(zipfile.ZipFile(z).namelist())"
['AGENTS.md', 'cmd/main/main.mbt', 'cmd/main/moon.pkg', 'h.mbt', 'LICENSE', 'moon.mod', 'moon.pkg',
 'moon_textstat.mbt', 'moon_textstat_test.mbt', 'moon_textstat_wbtest.mbt', 'README.mbt.md']
$ # docs/ 与 textstat/ 均不在包内
```

（该结论依赖「模块根位于仓库根之下」这一布局，其成立前提是 PRD-A 七、开放问题第 1 行「仓库归属」的用户裁决，见 §3.7 与设计文档第六节。）

### 1.3 L2 生成产物的身份

L2 不是上游字节的直接拷贝，因此它的身份必须单独固定，且必须能被「重跑生成器再比对」验证。

| 产物 | 生成规则（不含实现） | 当前可固定的量 | 待生成后固化的量 |
| --- | --- | --- | --- |
| CMUdict 音节表（裁剪形态） | 逐键取**首次出现**发音的音素数；仅保留「与断字回退值不等」的键 | 条目 48,202；未排序形式的字节数 515,949，SHA-256 `6167911da7a152ac247c084ac586ed64f370933233d9ec71324ca0e24c3db507`；不裁剪形态 123,455 条 / 1,292,929 字节 / SHA-256 `1d277f837ac1713d8b8b5777ab2761a8d7fc8ee4287c8a625dec320a0f5777ce` | **按字典序排序后行集合的 SHA-256**（`待生成后固化`）——排序形式才是可跨机器复现的形式 |
| 断字模式表（十二种语言） | 按各文件首行声明的编码解码后，逐模式行转写为 UTF-8 的字符序列 | 模式条数：en_US 11,125；de_DE 77,847；es 859；fr 2,908；it 420；nl 16,256；pl 4,823；ru 3,874；hu 102,204（九本合计 220,316）；另加 en_GB 14,057、de_AT 77,847、pt_BR 1,246（十二本合计 313,466） | 生成源文件的 SHA-256（`待生成后固化`） |

固定「条目数与未排序字节数」而不是全部锁死，是因为生成器尚未定型（本设计不含实现）；`待生成后固化` 是显式待办，不是省略。

**编码事实（必须记录，否则生成会静默出错）**：各断字模式文件的首行是编码声明，且**不全是 UTF-8**。实测：

```console
$ python -c "import os,pyphen;d=os.path.join(os.path.dirname(pyphen.__file__),'dictionaries');[print(f, open(os.path.join(d,f),'rb').read().split(b'\n',1)[0]) for f in ['hyph_en_US.dic','hyph_de_DE.dic','hyph_es.dic','hyph_fr.dic','hyph_it_IT.dic','hyph_nl_NL.dic','hyph_pl_PL.dic','hyph_ru_RU.dic','hyph_hu_HU.dic']]"
b'UTF-8'      (en_US)     b'ISO8859-1' (de_DE)   b'UTF-8'  (es)   b'UTF-8' (fr)
b'UTF-8'      (it_IT)     b'ISO8859-1' (nl_NL)   b'ISO8859-2' (pl_PL)  b'UTF-8' (ru_RU)  b'UTF-8' (hu_HU)
```

德、荷为 ISO8859-1，波为 ISO8859-2 —— 这三种文件里的高字节**不是合法 UTF-8**，无法直接写进 UTF-8 源码文件（初次尝试直接 decode UTF-8 时抛 `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xe4`）。因此 L2 的生成规则里「按声明编码解码后再转写」是硬要求，生成记录必须同时保存「源编码」与「模式条数」。

## 2. AD-2 对拍比较约定

### 2.1 比较单位

- 单元格 = `(样本 id, 字段名, 语种代码)` 三元组。
- 样本集 = 冻结 oracle 的 11 个样本（`docs/facts/oracle_smoke.json` 的 `samples[].id`）；语种探针 = 13 个语种代码（`lang_probes` 的键）。
- 一个单元格的「期望值」来自 L3 表；「实际值」来自被验证实现的同一次调用。
- 判定：单元格全绿 ⇒ 通过。

### 2.2 浮点比较规则（D-4 的落地，权威）

1. 两侧都把十进制文本解释为 **IEEE-754 双精度**。oracle 侧来自 JSON 的数值文本：把文件按**通用换行**读入后 `json.loads → json.dumps` 可**文本级**原样还原（403 个浮点叶值的最短往返表示全部保留）；但原文件是 **CRLF**（实测 5,011 个 `\r`），字节级往返**不相等**（原文件 133,102 字节，重排后 128,091 字节）。因此「还原」的定义是**解析后的数值相等**，不是文件字节相等。被测侧取自同一次计算的 `Double` 值本身。
2. 相等判定 = **位模式相等**（用无符号 64 位重解释后逐位比较）。
3. **禁止**：容差比较、四舍五入后比较、把两侧的十进制打印字符串直接比较、按有效位数截断。
4. 理由（实测）：打印规则确实不同。`Double::to_string` 的判定式是「十进制指数落在 `[-6, 21)` 时用定点，否则用科学记数，且整数不补 `.0`」（`C:/Users/Administrator/.moon/lib/core/builtin/double_ryu_nonjs.mbt:541`），而 Python `repr` 在 `1e-05`／`1e+16` 这类量级上就用科学记数并补两位指数。逐项对照实测：

5. 结论：**打印文本不是契约，双精度位模式才是契约**。因此 AD-2 的失败记录同时保存位模式与两侧各自的打印文本，判等只用位模式。

6. 与 oracle 覆盖面有关的边界：oracle 的数值文本里**没有任何指数记法**（实测 `-?\d+(\.\d+)?[eE][-+]?\d+` 命中数 = 0）、**没有 NaN / Infinity**（命中数 = 0）、**没有最短往返形态为 `-0.0` 的值**（唯一 `-0.0` 命中是 `-0.09940000000000015` 的子串）。因此上表中三类打印差异**在当前样本集上不会被触发**；它们仍是必须登记的复开条件（见 §2.4）。

### 2.3 非浮点比较规则

| 类型 | 规则 |
| --- | --- |
| 整数计数 | 按值相等（不做范围、不做近似） |
| 去重难词列表（PRD-A FR-12） | 按**集合**比较：元素集合相等即通过；**不比较顺序**（理由见 §2.4 第 1 行） |
| 非去重难词列表（PRD-A FR-13） | 按**逐位序列**比较（顺序与长度都要相等）——upstream 该路径来自 `list`，顺序确定 |
| 未覆盖字清单（PRD-B FR-06） | 按逐位序列比较（定义即「首次出现顺序」，无 oracle 依赖，手算复核） |
| 字符串（如语种根） | 按 Unicode 码位序列相等 |
| 布尔 | 相等 |

### 2.4 已知的系统性差异：是否登记为「边界」

| 差异 | 处置 | 理由与实测 |
| --- | --- | --- |
| `-0.0` 的打印符号 | **不作为边界**（位模式比较下自然正确；oracle 无此值） | 若实现产生 `-0.0` 而 oracle 为 `0.0`，位模式不同 → 判失败，这是正确行为。等 oracle 出现 `-0.0` 时再议 |
| 指数记法 / 尾 `.0` | **不作为边界**（位模式比较不受影响） | 见 §2.2 第 5 条；把打印差异当边界会掩盖真实偏差 |
| 去重难词列表的顺序 | **登记为边界，且是 PRD 级开放项** | 实测：同一文本在 `PYTHONHASHSEED=0` 与 `=1` 下 `difficult_words_list` 顺序不同，且**两者都与已冻结 oracle 的顺序不同**（11 个样本中 6 个样本受影响的字段仅此一项；除该字段外两 seed 输出 0 处不同）。见设计文档第六节与第十一节 |
| 语种代码 `en`（无地区后缀） | **登记为边界** | 实测：Pyphen 的短名回退把 `en` 指向 `hyph_en_GB.dic`，`en_US` 指向 `hyph_en_US.dic`；两者的 `positions()` 在测量宇宙 3,045 词中有 12 个词不同，导致 `hyphenated_words` 样本音节数 38 → 32、FRE `9.101617647058845` → `38.960441176470624`。见设计文档 D-15 |

### 2.5 失败记录 schema 与断言

**每条失败记录必含的字段（PRD-A 失败可诊断性 NFR 的七项）**：`输入文本的 SHA-256`、`样本 id`、`指标名`、`语种代码`、`期望值`、`实际值`、`后端 target`。

**浮点单元格额外两项**：`期望位模式（16 位十六进制）`、`实际位模式（16 位十六进制）`。**不得**写入原文（PRD-A 10.7 与 PRD-B 10.7 均声明错误信息与失败记录只含哈希与指标名，不含原文）。

**落盘与可检索**：失败记录文件按固定命名规则落盘（建议 `_gate/failures-<后端>-<时间戳>.jsonl`，一单元格一行），可被 `grep` 按指标名命中。

**断言 A2-1（失败可诊断性）**：人为注入一处分档或语种边界偏差后，失败记录文件存在、每条记录七项字段非空、按指标名 grep 能定位、记录数等于失败单元格数。

```console

EXIT=1
$ grep -c '"metric":"flesch_reading_ease"' _gate/failures-native-*.jsonl
1
```

- **期望失败退出码 = 1**。注入前同一命令 **= 0**。（该断言在门禁程序落地前为 `未干跑`。）

**断言 A2-2（比较器自证）**：对 §2.2 对照表中「一致」的 6 个值，两侧位模式必须相等；对「不一致（记法）」的 11 个值，位模式仍必须相等（证明比较器不受打印差异影响）。

## 3. AD-3 门禁命令约定

### 3.1 唯一权威命令

```
moon run cmd/gate --target native
```

- 执行位置：MoonBit 模块根（含 `moon.mod` 的目录）。
- 必须显式给出 `--target native`：默认 target 走 wasm 执行后端，而 `moonrun.exe` 在本机加载即失败（`0xC0000139`），默认 target 的 `moon test` 为 EXIT=255（`docs/facts/moonbit-compile-probe.md:433-437`）。**不带 `--target` 的运行不构成门禁证据。**
- `moon run` 的 native 路径已实测可用：`moon run cmd/main --target native` → 正常输出、`EXIT=0`（`docs/facts/moonbit-compile-probe.md:323-325`）。

### 3.2 退出码语义

| 退出码 | 含义 | 处置 |
| --- | --- | --- |
| 0 | 全部单元格一致，且运行完整性检查通过 | 门禁通过 |
| 1 | 存在单元格不一致；失败记录已落盘 | 门禁失败，按失败记录定位 |
| 2 | 环境或构建失败（编译失败、后端不可用、期望值表缺失） | **不得当作通过**；修复环境后重跑 |
| 其他非零 | 同上按失败处理 | 不得当作通过 |

### 3.3 运行完整性（关闭「空跑通过」这一漏洞）

实测陷阱：模板自带的空测试文件会让 `moon test` 打印 `Warning: no test entry found.` 并 **EXIT=0**（`docs/facts/moonbit-embedding-and-naming-probe.md` §8），即「没有测试」与「测试通过」在退出码上不可区分。因此：

- 门禁的**第一行输出**必须是规范调用串 `moon run cmd/gate --target native`，随后输出 `cells=<总数> passed=<通过数>`。
- 门禁必须把 `<总数>` 与**冻结的最小单元格数**比较，低于即 EXIT=2。
- **冻结的最小单元格数 = 366**。组成见 §5：样本侧 288（12 组 × 24 个 `[ALIGN]` 形态）+ 语种侧 78（13 个语种代码 × 6 个 `[ALIGN]` 字段）。门禁自报的 `cells=` 必须 ≥ 366，否则 EXIT=2。
- `[ALIGN]` 单元格以外的 oracle 数据（31 个 `[EXT]` 调用形态 × 11 样本 + `results_es` 组的 31 个形态，以及语种探针里的 `count_arabic_syllables` / `osman` / `easy_words_count` / `lang_root` 四项）**不作为断言单元**，登记理由见 §5。实现方不得为这些单元格构造期望值。
- **中文组自报自己的 192 个单元格，`floor=366` 不变**（v1.5）：`--group=zh` 的单元格是 16 个用例 × 12 个 `zh_` 字段，由中文组自己统计并以 `cells=192 passed=192 floor=366 group=zh inject=0` 自报。366 保护的是**有 oracle 的英文 L3 表**（`@gate_data.total_cells()`），中文组既不进那张表，也不抬高这个数；中文组「不会空跑通过」由两件事保证——自报的 192 是它自己的选择集大小，以及 `--group=zh --inject=1` 必红（§6、spec §4.7.2）。实跑：`cells=192 passed=192 floor=366 group=zh inject=0`、`EXIT=0`；注入后 `cells=192 passed=191`、`EXIT=1`。

### 3.4 期望值来源与「不读 oracle 原始文件」

- 门禁的期望值来自 L3（随源码固化的生成表），**不读取 `docs/facts/oracle_smoke.json` 原始文件**。理由：(a) 库运行时不得读文件（PRD-A 安全性 NFR），(b) 把 oracle 文件的行尾/寻径差异挡在门禁之外，(c) 使门禁在模块目录内自足可跑。
- oracle 原始文件的身份由其上游语料（§1.2 的 CMUdict 与字典哈希）与生成器版本共同固定；L3 的身份由 §1.3 固定。
- 输入样本文本也随源码固化，且按**解析后的字符串**使用（不依赖文件行尾）。

### 3.5 次选后端

- `moon test --target js` 仅作为**次选**证据，且必须满足：PATH 上 `node` 是真 node（实测 v22.13.1 可用），且 `C:\Users\Administrator\.bunpm\bin` 不在 PATH 上（该 shim 指向不存在的 `D:\nvm4w\nodejs\bun`；实测「只把真 node 目录 prepend、不剔除 `.bunpm`」仍失败）。
- js 次选**不阻塞**门禁结论与发布。
- `wasm` / `wasm-gc`：**不可达**（`moonrun` 加载失败 `0xC0000139`），构建成功不构成执行可用证据（PRD-A 兼容性 NFR (b)）。

### 3.6 断言

**断言 A3-1（门禁单命令性）**：存在且仅存在一条门禁命令，即 §3.1；直接调用 `moon fmt` / `moon check` / `moon test` 不构成门禁证据。

```console
$ moon fmt --check && moon check --target native && moon test --target native   # 这些都不是门禁
```

**断言 A3-2（门禁自描述串与本文档同步）**：门禁首行打印的规范调用串必须与本文档 **§3.1 代码块**中的字符串逐字相同。为防止「文档里同一串出现多次」造成的自指失败，检索范围限定在 §3.1 小节内（`### 3.1` 到 `### 3.2` 之间），期望命中数定义为常量 **AD_A3_2_EXPECTED_HITS = 1**。

```console
$ moon run cmd/gate --target native --group=selfcheck | head -1
moon run cmd/gate --target native
$ sed -n '/^### 3.1/,/^### 3.2/p' docs/superpowers/designs/202610201517-moon-textstat-移植-数据与门禁约定.md \
    | tr -d '\r' \
    | grep -c '^moon run cmd/gate --target native$'
1
```
- **行尾前置**：工作副本为 CRLF（`core.autocrlf=true`，本文件实测 481 个 `\r`），行尾 `\r` 会使 `$` 锚点落不住，因此断言命令**必须先剥 CR**（`tr -d '\r'`）。不加 `tr` 时同一条命令实测返回 **0**（`grep` EXIT=1），会误判为「文档里没有该串」。
- 实测（本版本文档）：加 `tr -d '\r'` 后限定区段命中数 = **1**，与常量 `AD_A3_2_EXPECTED_HITS` 一致；不加限定直接全文 `grep -c` 会得到 **3**（①§3.1 代码块、②本断言的 console 块、③§6 自报格式块；实测 `grep -n '^moon run cmd/gate --target native$'` 命中第 303/352/432 行），故**禁止**用全文检索作为该断言的判据。
- **期望失败退出码 = 1**（门禁打印串与文档不一致、或区段命中数 ≠ 1 时）。当前状态 `未干跑`（门禁程序尚未落地）。

**断言 A3-3（注入偏差必失败）**：由门禁自带的注入开关制造确定数量的偏差，再撤除；分两条命令、两个期望结果。

```console
$ moon run cmd/gate --target native --group=selfcheck --inject=1 | tail -1 ; echo EXIT=${PIPESTATUS[0]}
cells=366 passed=365 floor=366 group=selfcheck inject=1
EXIT=1
$ grep -c '"injected":true' _gate/failures-native-*.jsonl
1
$ moon run cmd/gate --target native --group=selfcheck | tail -1 ; echo EXIT=${PIPESTATUS[0]}
cells=366 passed=366 floor=366 group=selfcheck inject=0
EXIT=0
```
- `--inject=<n>` 的语义见 §6：在内存中把第 n 个期望单元格改成一个与其实际值位模式不同的值，报告里以 `injected=true` 标注；**不得写入任何生成产物文件**（否则违反「生成物禁手改」）。
- **期望结果**：注入时 EXIT=1 且失败记录恰好 1 条；未注入时 EXIT=0。当前状态 `未干跑`（门禁程序尚未落地）。

## 5. `[EXT]` 调用形态白名单（不进入断言）

R-07 的裁决：L3 只固化 `[ALIGN]` 调用形态的单元格。上游 oracle 每个样本记录 55 个调用形态，其中 **31 个属于 `[EXT]` callable**；这 31 个形态在本约定中显式登记为「不进入断言」，并以固定清单的形式约束实现方，避免误建期望值。

| 组 | `[EXT]` 调用形态（oracle `results` 的键） | 不进入断言的理由 |
| --- | --- | --- |
| 上游派生平均量（7） | `avg_character_per_word`、`avg_letter_per_word`、`avg_sentence_length`、`avg_sentence_per_word`、`avg_syllables_per_word`、`avg_syllables_per_word[interval=100]`、`words_per_sentence` | PRD-A 10.3 未定义字段，G-01/G-02 不要求；公式内部使用同一算式 |
| 单词判定与变换（4） | `is_difficult_word`、`is_easy_word`、`remove_punctuation`、`miniword_count` | 单词语义校验/变换/短词计数，PRD 未要求 |
| 阿拉伯语（4） | `count_arabic_long_words`、`count_arabic_syllables`、`count_complex_arabic_words`、`count_faseeh` | PRD-A C3 明列为非目标 |
| 清单外公式（16） | `crawford`、`fernandez_huerta`、`gulpease_index`、`gutierrez_polini`、`lix`、`mcalpine_eflaw`、`osman`、`rix`、`spache_readability`、`spache_readability[float_output=False]`、`szigriszt_pazos`、`text_standard`、`text_standard[float_output=True]`、`wiener_sachtextformel[variant=1]`、`wiener_sachtextformel[variant=4]`、`dale_chall_readability_score_v2` | PRD-A C3 明列为非目标 |
| 合计 | **31 个形态** | — |

`[ALIGN]` 的 **24** 个形态：`automated_readability_index`、`char_count`、`char_count[ignore_spaces=False]`、`coleman_liau_index`、`dale_chall_readability_score`、`difficult_words`、`difficult_words_list`、`flesch_kincaid_grade`、`flesch_reading_ease`、`gunning_fog`、`letter_count`、`lexicon_count`、`lexicon_count[removepunct=False]`、`lexicon_count[split_contractions=True]`、`lexicon_count[split_hyphens=True]`、`linsear_write_formula`、`linsear_write_formula[strict_lower=True,strict_upper=True]`、`long_word_count`、`monosyllabcount`、`polysyllabcount`、`reading_time`、`sentence_count`、`smog_index`、`syllable_count`。

语种探针侧的 `[ALIGN]` 字段为 **6** 个：`syllable_count`、`flesch_reading_ease`、`gunning_fog`、`difficult_words`、`polysyllabcount`、`monosyllabcount`；`count_arabic_syllables`、`osman`、`easy_words_count`、`lang_root` 四个字段不进入断言（前两者属 `[EXT]` callable，后两者是诊断量而非指标）。

**单元格总数（冻结下限的推导）**：样本侧 = 12 组 × 24 = **288**（11 个样本的 `results` + `spanish_text` 的 `results_es`）；语种侧 = 13 个语种代码 × 6 = **78**；合计 **366**。

**机器可检形式**：oracle 每个样本的 `results` 键数必须等于 55，其中落在上表 `[EXT]` 清单内的键数必须等于 31、其余必须等于 24。命令与期望输出见 §3.3 与本表；任一侧数目不符即说明上游 oracle 版本漂移，必须重开本文档。

## 6. 门禁参数契约（`--group` / `--bench`）

门禁程序必须接受下列参数，且参数集合是**封闭**的；未知参数以 EXIT=2 结束。

| 参数 | 取值 | 语义 | 与验收维度的对应 |
| --- | --- | --- | --- |
| `--group=all` | 默认值 | 全部 `[ALIGN]` 单元格 | — |
| `--group=count` | — | 计数层 24 形态中的计数组 | A-2 |
| `--group=variant` | — | `lexicon_count` 三变体 + `char_count[ignore_spaces=False]` + Linsear 双开关 | A-2 |
| `--group=formula` | — | 8 公式及其变体 | A-3 |
| `--group=lang` | — | 13 个语种代码 × 6 字段 | A-4 |
| `--group=degenerate` | — | 空串 / 纯空白 / 纯标点 / <5 词 四组 | A-5 |
| `--group=errors` | — | 不受支持语种的显式失败 | A-5 |
| `--group=data` | — | 数据身份的抽查子集 | A-1 |
| `--group=selfcheck` | — | **全量 366 单元格 + 完整性检查**（首行串、计数下限）；`--inject=<n>` 在此组与 `zh` 组成效 | A-6 |
| `--group=zh` | — | **中文 192 个单元格**（16 用例 × 12 个 `zh_` 字段，spec §4.7.6）；不进 L3、不抬高 366 | A-Z1 |
| `--bench` | 标志 | 性能采样（100 次取中位数），不参与对拍 | A-9 |

自报格式（固定两行）：

```
moon run cmd/gate --target native
cells=<总数> passed=<通过数> floor=366 group=<id> inject=<n>
```

- **首行恒定**为规范调用串（不含任何参数），供 A3-2 逐字比对；第二行才是自报行，携带实际使用的 `group` 与 `inject`。
- `cells >= floor` 否则 EXIT=2；`passed < cells` 时 EXIT=1 并写失败记录。
- `--inject=<n>`：在内存中把第 n 个期望单元格改成与其实际值位模式不同的值，并置 `inject=<n>`；**不得写入任何生成产物文件**。`selfcheck` 组全量运行时，`--inject=1` 使 `passed=365`、`cells=366`；`zh` 组运行时，`--inject=1` 使 `passed=191`、`cells=192`（两组语义相同，各自在自己的选择集内扰动）。

| 红线 | 约束 | 权威源 | 可机检形式 |

| DR-R1 | 模块名必须满足包 ID 语法：首字符 ASCII 字母或 `_`，其后字母/数字/`-`/`_` | 编译器报错原文（`moon new --name 1abc p`） | `moon new --name <候选> p; echo EXIT=$?` 期望 0；非法名 EXIT=255 且输出含 `Names must match package id syntax:` |
