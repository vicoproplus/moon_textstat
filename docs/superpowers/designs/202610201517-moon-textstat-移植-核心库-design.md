## 一、用户当前理解（认知校准）

### 1.1 这个移植真正要交付的是什么

交付物是一个**可安装的 MoonBit 包**：调用方给一段文本和一个语种代码，拿到一组确定的数值——10 个计数量、8 个公式分、1 个阅读时长，以及一个可选的去重难词列表。它必须离线、无第三方运行时、在 native 与 js 两个后端上给出**与冻结的 Python 0.7.13 逐位相同**的双精度结果（PRD-A G-01、G-02、G-04、G-05）。

### 1.2 难点不在八个公式

八个公式都是教科书线性式，且上游实现短到可以逐行读完（`textstat/textstat/backend/metrics/` 下每个文件 9–83 行）。真正决定成败的是三处**隐式口径**，它们在原实现里没有任何显式声明：

| 隐式口径 | 上游落点 | 一旦理解错的后果 |
| --- | --- | --- |
| 什么算一个词 | `backend/selections/_list_words.py:48-56` + `backend/transformations/_remove_punctuation.py:33-42`：先按可选开关替换连字符、再用 `[^\w\s]` 删标点、再 `str.split()`。`\w` 含数字与下划线，所以 `$1,299.99` → `129999` 是一个词，`well-known` → `wellknown` 是一个词 | 词数、每词字符数、难词集全部漂移；ARI 与 Coleman-Liau 分母口径还互不相同 |
| 什么算一句 | `backend/counts/_count_sentences.py:24-32`：正则 `\b[^.!?]+[.!?]*`，只认 `.` `!` `?`；**词数 ≤ 2 的候选片段被丢弃**；最后 `max(1, ...)` | 句数是 SMOG / Linsear / ARI / Coleman-Liau / FRE / FK 的分母，差 1 句就是整片数值漂移 |
| 什么算一个音节 | `backend/counts/_count_syllables.py:23-34`：**逐词先查 CMUdict 首选发音的音素数，未命中才退回断字位置数 + 1** | 见下节，这是唯一真正有技术分叉的地方 |

还有第四处不是「口径」而是「约定」：Python 双精度的**二进制残差本身就是对外契约**。`_legacy_round` 在默认配置下是恒等函数（`textstat/textstat.py:101-103`，`__round_points is None`），所以 `116.14500000000001` 这样的尾数必须原样产出，不能「修正成」`116.145`。

### 1.3 唯一真正有风险的技术分叉：音节来源

上游的音节是**两层**：发音优先、断字回退。去掉任一层都会破坏位级一致，而且两层的失效方向不同：

- 只留断字（Pyphen-only）：词级失配 10.540449815374286 %（314 / 2,979 个命中词），方向 305 偏低 / 9 偏高，公式级最大绝对差 **18.800000**（FRE，`multiple_paragraphs_newlines`），8 个样本里只有 3 个全公式位级一致（`docs/facts/syllable-strategy-evidence.md:35-37,54-55,208,238-243,372`）。
- 只留发音、去掉回退（CMUdict-only）：`hyphenated_words` 样本 FRE 从 `9.101617647058845` 变成 `123.5604411764706`，最大绝对差 **114.458824**（`docs/facts/syllable-strategy-evidence.md:192,239,371`）。原因很直白：该样本里 `costeffective` / `highperformance` / `selfcontained` / `stateoftheart` / `twentyfiveyearold` / `userfriendly` / `wellknown` 七个连字符复合词在 CMUdict 里根本没有键。

所以「音节怎么来」不是风格选择，而是**唯一能同时满足 PRD-A G-01 与 FR-07 的组合只有「完整发音词典 + 完整断字引擎」**。D-1 与 D-2 的论证都围绕这一句展开。

## 三、关键约束

### 3.1 技术约束

| 约束 | 事实与出处 | 对设计的影响 |
| --- | --- | --- |
| 工具链版本 | `moon 0.1.20261012 (748b63c 2026-10-12)`；`moonc v0.10.15+943464bfa (2026-10-12)`（`docs/facts/moonbit-compile-probe.md:12-19`） | 所有工具行为结论只对这两个版本成立；升级即触发 D-8 复开 |
| 可用的测试后端只有 native 与 js | `moon test --target native` EXIT=0、断言失败 EXIT=2；`--target js` 在真 node 下同样 EXIT=0/2；`wasm`/`wasm-gc`/默认 target 均 EXIT=255（`docs/facts/moonbit-compile-probe.md:433-437`，本设计期间复测一致） | D-8：门禁钉 native |
| `moonrun` 在加载阶段即失败 | `0xC0000139`（`STATUS_ENTRYPOINT_NOT_FOUND`），bash 侧看到 57；`moonrun.exe` 任何参数都跑不到（`docs/facts/moonbit-compile-probe.md:195-207`） | wasm 系「构建成功 ≠ 可执行」，PRD-A 兼容性 NFR 已把它写成判据 |
| 工程文件名 | `moon.mod` / `moon.pkg`（不是 `.json` 后缀）（`docs/facts/moonbit-compile-probe.md:63`） | 本文件一律用新名 |
| `moon.mod` 不接受 `files` 键 | 追加 `files = [...]` 后 `moon check` EXIT=255，报错 `Unexpected key 'files' found in moon.mod.`（`docs/facts/moonbit-embedding-and-naming-probe.md` §2） | 包内容无法用清单收窄 → D-3 与 D-11 必须靠**目录位置**而不是清单来隔离 |
| `moon package` 会把模块目录内所有非忽略文件打进包 | 实测 `data/`、`_data/`、`internal/` 均入包；误放的 26 MB `nodereal/node.exe` 也入包；`.gitignore` 命中的目录不入包（同上 §2） | 交付前必须有「包内容清单核对」这一步（WB10） |
| 单行文本段有列上限（不是「字面量长度」上限） | 触发点是**行内第 65,535 列**：`let a : String = "<L>"`（17 字符前缀）下字面量 L=65,515 通过、L=65,516 失败；`pub let b : String = "<L>"`（21 字符前缀）下 L=65,511 通过、L=65,512 失败；报错为 `E0033`（`text_segment_excceed`，列 65535），`-d` 下 EXIT=255。权威登记见 AD 红线表 DR-R3/DR-R4 | D-3 的嵌入格式必须保证**每行长度 < 65,535 列**（取 ≤ 1,000 字符/行即远超安全余量）；探测文件必须给每个绑定使用点，否则先报 `E0002` 而造成边界不可复现 |
| 分块字面量没有总量问题 | 4,000 × 1,000 字符（源文件 4,028,135 字节）在 `-d` 下 `moon check` EXIT=0（0.435 s）、`moon build --target native` EXIT=0（0.761 s）（同上 §3） | 全部数据内嵌在编译期与体积上可行 |
| 多包布局可用 | 子目录放**空** `moon.pkg` 即成新包，包名为 `<module>/<dir>`（同上 §4） | D-11 的包划分成立 |
| 空跑测试会被误判为通过 | 只有空测试文件时 `moon test` 打印 `Warning: no test entry found.` 并 **EXIT=0**（同上 §8） | AD-3 必须自带「单元格计数下限」检查，否则门禁可能空转通过 |
| 行尾风险 | `core.autocrlf=true`（仓库与全局），无 `.gitattributes`；检出到工作区即 CRLF（`docs/facts/env-baseline.md:721-765`） | D-9；且上游两份易读词表的工作区形态与 git blob 形态**字节数不同**（21,577 vs 18,637；208,126 vs 188,126，实测） |
| Python 浮点打印是契约的一部分 | `116.14500000000001` 等残差是 observable（`docs/facts/upstream-api-inventory.md:863-865`） | D-4 的核心 |
| 字节级差异的两侧打印规则不同 | MoonBit `Double::to_string` 用 `exp ∈ [-6,21)` 判定点/科学记数且整数不补 `.0`（`C:/Users/Administrator/.moon/lib/core/builtin/double_ryu_nonjs.mbt:541`）；Python `repr` 在 `1e-05`/`1e+16` 即用科学记数 | D-4 必须用位模式比较，不能用字符串比较 |
| 打包语言的字典编码不统一 | 首行声明：de/nl = ISO8859-1，pl = ISO8859-2，其余 UTF-8（本设计实测，详见 AD 文档 §1.3） | D-17：生成步骤必须按声明编码解码 |

## 五、验收场景（回链 PRD US-XX）

本表只做「验收载体映射」，不新增验收标准。载体三种：**oracle 单元格比对**（与冻结 oracle 逐单元格比）、**手算复核**（按 PRD 定义人工推导后比对，用于无 oracle 的中文指标）、**安装即运行**（空工程安装后执行 README 示例）。

| PRD 条目 | 设计层验收载体 | 具体单元格/步骤 | 判定命令 |
| --- | --- | --- | --- |
| PRD-A US-01（批量基础统计） | oracle 单元格比对 | 11 个样本 × 计数类调用形态（`char_count`、`letter_count`、`lexicon_count`、`sentence_count`、`syllable_count`、`polysyllabcount`、`monosyllabcount`、`difficult_words`、`long_word_count`、`reading_time` 及其变体开关） | AD-3 门禁 |
| PRD-A US-02（八公式） | oracle 单元格比对 | 11 样本 × 8 公式 = 88 单元格；退化输入四行（空串 / 纯空白 / 纯标点 / <5 词）单独计数 | AD-3 门禁 |
| PRD-A US-03（多语言） | oracle 单元格比对（语种探针） | 13 个语种代码 × 探针字段（音节、FRE、Fog、难词、多音节、单音节）；外加 `spanish_text` 的 `results` 与 `results_es` 两组 | AD-3 门禁 |

| PRD-A US-06（数值可直接呈现） | oracle 单元格比对 + 单位核对 | 数值与 10.3 单位表逐字段核对（年级允许非整数；阅读时长单位秒） | AD-3 门禁 + 人工核对 |

### 栏 2：交付结构可达性（PRD 单元划分与交付顺序是否使某单元验收不可达）

**PRD-B 10.6 声明「中文基线不依赖核心库单元的公式实现」——本设计核验该声明：结论是「对公式成立，对交付结构不成立」。**

- 核验依据：PRD-B FR-07 的验收是「**单次调用返回的字段集合**包含 10.3 列出的全部英文指标字段与全部中文字段」。这个「单次调用 + 同一对象」正是 PRD-A 10.6 判给单元 A 独占的「指标输出值对象的字段契约」。
- 推论：只要 FR-07 按字面执行，**单元 B 的 P0 验收就无法在单元 A 的值对象存在之前完成**；这与 PRD-B 10.6「两个单元各自独立实现、各自可验收，不存在先做 A 再做 B 的阶段关系」直接冲突。
- 两条可能的读法：
  - **(i)** FR-07 读作「当两个单元都在场时，字段并入同一对象」；单元 B 的**独立交付物**是它自己的函数，只返回 `zh_` 前缀字段；合并后的单次调用是**集成**阶段的产物，不是 B 的独立验收门槛。
  - **(ii)** 两单元并非独立可交付：B 必须等 A 的值对象定型。
- **本设计推荐 (i)**，理由：它保住了「B 可独立实现与独立验收」（B 的分句、句长、覆盖率都能只用手算夹具验收，PRD-B B-06 已说明无中文 oracle），同时把「同一对象」降级为集成验收项，与 10.6 的「边界」语义一致。
- 该推荐已由 PRD-B 处置为两阶段条款（见七之三 C-5），**不再是待裁决项**；D-13 与 WB8 已按「A 不预留中文字段、B 自带 `zh_`-only 入口」更新。

## 八、降级等价与数据流方向

### 8.1 降级路径：音节的两层不是「退化」，是 oracle 语义

必须先把话说清：上游的音节是**主路径 + 回退**，回退是**正常语义的一部分**，不是「降级到差不多」。因此在设计里它不是「等价近似」，而是「必须精确复刻的两条分支」。

| 编号 | 触发条件 | 可观察行为 | 等价性 | 违反后果 |
| --- | --- | --- | --- | --- |
| FE1 | 词不在发音词典中（实测宇宙内 3,023 词里有 **44** 个，例如 `armful`、`bumblebee`、`chipmunk`、`wellknown`、`tolkien`、`flip-flop`） | 该词音节数 = 断字位置数 + 1（`_count_syllables.py:32-33`） | **精确等价**（不是近似） | 关掉回退即破坏 PRD-A FR-07：`hyphenated_words` 样本 FRE 从 `9.101617647058845` 变 `123.5604411764706`，最大绝对差 **114.458824**（`docs/facts/syllable-strategy-evidence.md:192,239`） |
| FE2 | 语种常量或易读词表在该语种根下缺失 | **静默降级**：常量取英语（`_get_lang_cfg.py:22-30`），易读词表取英语并给出告警（`_get_lang_easy_words.py:46-54`）。实测 `pl_PL` 的 FRE 用英语常量；`de_DE`/`fr_FR` 等的易读词表条目数都是 2,941 | **精确等价**（必须复刻） | 改成「报错」会让 `pl_PL`、`de_DE` 等 8 个语种根的 FRE 全部不可达（PRD-A FR-24 验收） |
| FE3 | 断字引擎没有该语言的字典（`ar`、`xx_YY`） | **显式失败**：上游抛 `KeyError: None`（`_get_pyphen.py:22`）；同一语种下 `count_arabic_syllables` 仍正常返回（它不读 `lang`） | **精确等价**（必须复刻失败，不得静默成功） | 改成「返回英语结果」会让 PRD-A US-03 第三条与 FR-28 的判别力归零 |

补充两条易被误当「降级」的行为，实际是**公式自身的分支**（不是本设计的降级项，仅登记以免被误改）：

- 空串/纯空白/纯标点的分母为零分支：FRE/FK/Fog/ARI/Coleman/Linsear/Dale-Chall 返回 `0.0`，SMOG 在「非空但零多音节」时返回常数项 `3.1291`，Linsear 在纯标点时返回 `-1.0`（`docs/facts/upstream-api-inventory.md:911-921`）。
- `pl` 只有 `syllable_threshold` 一个键，FRE 三常量继承英语（`backend/utils/constants.py:51-53`）。

**禁止的「改进」**：给 FE2 加错误、给 FE3 加回退、给 FE1 加「启发式音节估计」——启发式（如元音组）与断字回退是**两套不同口径**，且**都不是** oracle 行为；任何一个替代都会破坏 FR-07 与 G-01 的位级一致。（本文件不给出两者的失配率：抽样口径不可复现，宁可删数也不留无源数字。）

### 8.2 数据流方向

**`N/A — no sensitive data flow`。**

理由（PRD 10.7 = 无，两份 PRD 均如此声明）：

- 库是纯本地计算：输入文本只在进程内参与计数与查表，不上传、不落盘、不做遥测、不读取用户环境。
- 本设计额外确认：D-3 选择「全部数据内嵌」后，**运行期零文件读取、零网络**，因此不存在「数据从哪来」的运行期路径；数据只在编译期进入二进制。
- 失败记录由**开发期**门禁程序产生，不属于库运行时行为（PRD-A 安全性 NFR 明文）。

因此本节不画数据流图：没有跨越信任边界的数据移动。

## 十一、双形态契约权威裁决

### 11.1 识别到的双形态

本项目的门禁确实以两种形态存在：

| 形态 | 载体 | 谁在读它 |
| --- | --- | --- |
| (i) 文档命令 | 《…数据与门禁约定》§3.1 的代码块 `moon run cmd/gate --target native` | spec 作者、评审者、CI 配置作者 |
| (ii) 仓库程序 | `cmd/gate`（MoonBit 可执行包） | 执行者、CI |

### 11.2 裁决

- **权威 = (i) 文档命令**。它是「什么是门禁」的定义：命令、target、退出码语义、运行完整性下限。
- **(ii) 降级为「派生物/实现」**：程序必须服从文档；程序不能定义新的通过条件，也不能因为「实现上不方便」而改变退出码语义。
- **同步机制（唯一的机器检查）**：门禁程序**第一行输出必须是它自己的规范调用串**，且该串必须与 AD 文档 §3.1 的代码块**逐字相同**；AD-3 的断言 A3-2 用 `head -1` 与 `grep -c` 做机器比对。任何一方改动而另一方未跟随时，A3-2 失败（EXIT=1）。

### 11.3 为什么不反过来（程序为权威）

若以程序为权威，则「门禁是什么」只能靠读代码得知；而 PRD-A FR-30 要求「门禁的退出状态与比对结果一一对应」是**可评审的契约**，不是实现细节。此外，文档为权威时，spec 可以逐字引用一条命令；程序为权威时，spec 只能引用一个路径，评审者无法在 diff 中看到「门禁语义是否被改动」。

### 11.4 其他候选双形态（已排查，均不成立）

| 候选 | 是否为双形态 | 处置 |
| --- | --- | --- |
| 字段契约（PRD 10.3 vs 代码里的字段名） | 否——PRD 是唯一权威，代码是派生 | 由 AD-4 的负承诺封死（不另立第三份） |
| oracle 数值（`oracle_smoke.json` vs L3 期望值表） | 否——JSON 是源，L3 是派生物 | L3 的身份由 AD-1 §1.3 固定；门禁不读 JSON（AD-3 §3.4） |
| README 示例（README vs 示例程序） | 否——示例程序是唯一可执行体，README 引用它 | 由「安装即运行」验收覆盖（US-04） |

## 十三、平台接缝与渲染接缝

### 13.1 PS1-PS3 平台接缝

**结论：本库不含任何平台条件编译分支。** 证据：

| 编号 | 断言 | 证据 |
| --- | --- | --- |
| PS1 | 设计不依赖任何宿主 API（时间、随机、环境变量、进程、文件、网络） | PRD-A 安全性 NFR 明文禁止网络/写文件/执行输入；D-3 选择内嵌数据后连读文件也不需要。MoonBit 核心库中确实存在 `env` 包（`args`/`get_env_var`/`now`/`rand`），本设计**不引用**其中任何一项 |
| PS2 | 设计不需要 `extern "js"` 或任何 FFI | 全部计算是字符串/整数/浮点运算；唯一的平台相关行为是 `Double::to_string`，它由核心库在 js/non-js 两侧各自实现（`double_ryu_js.mbt:16` 用 `number.toString()`，`double_ryu_nonjs.mbt` 用 Ryu 实现），本库只是调用它，不自己分支 |
| PS3 | 无平台条件编译（`moon.pkg` 的 `options(targets: …)` 仅用于测试文件排除时也非产品面） | 本设计不引入任何按 target 分文件的源码面 |

若未来引入 FFI 或平台 API（例如改为运行时读字典），**第十四节的门禁必须重跑**。

### 13.2 TB1-TB3 测试环境接缝

这是**验证接缝**，不是产品接缝。

| 编号 | 后端 | 可达性 | 处置 |

## 十四、外部契约真值源与传输形态

### 14.1 SD1-SD2 外部桥接

**`N/A — no external bridging surface.`**

理由与验证：

- 目标只有 MoonBit（PRD-A G-05：调用方依赖清单中只有 MoonBit 模块）。
- 设计不调用任何「外部注入的桥接 API」（宿主运行时注入的全局、原生桥、平台注入对象）。
- 设计不含任何 `extern "js"` / FFI 声明（见 PS2）。
- 唯一的跨语言接触面是**开发期**的 Python oracle 生成器（`docs/facts/gen_oracle_smoke.py`），它不进入交付物，也不构成运行期桥接。

**若后续决策引入 FFI**（例如为体积改为运行时读字典、或为性能接原生库），本节必须重跑：届时需要回答「谁注入、注入什么类型、失败如何表现」三个问题。

### 14.2 E8 传输形态

**`N/A — no cross-runtime transfer mechanism (no streaming / long-connection / chunked / batch transfer); the library is a pure in-process function library.`**

理由：输入是一个字符串，输出是一个值对象，全部在进程内完成；没有序列化协议、没有分片、没有连接、没有批处理队列。数据（字典/词表）在**编译期**进入二进制，不经过任何传输通道。
