## 一、用户当前理解（认知校准）

### 1.1 这个单元真正要交付的是什么

交付物是**同一模块内的一个新子包**：调用方给一段中文文本，一次拿到 12 个 `zh_` 前缀字段——句数、句长和、句长均长、四个长度档计数、汉字总字数、不同汉字数、命中常用字数、覆盖率、未覆盖字序列。它必须离线、无第三方运行时、不读文件、结果只依赖输入（PRD-B G-01、G-02、G-05）。**随包版本（已核对已发布包）**：该子包首次随包发布是在 **0.2.0**（`moon view vicoproplus/moon_textstat` → `@0.2.0`、Published `2026-10-26T07:19:56Z`、Versions: 2；`lib/_build/publish/vicoproplus-moon_textstat-0.2.0.zip` 共 109 条目，其中 `zh/` 与 `gate/zh/` 前缀者 13 条，包内 `moon.mod` 为 `version = "0.2.0"`；0.1.0 的 zip 内 `zh` 条目 0 条），因此 0.1.0 里没有这 12 个字段。

与单元 A 的根本差别不在难度，而在**没有 oracle**：`docs/facts/oracle_smoke.json` 的 11 个样本里含 CJK 字符的样本数为 0（PRD-B B-06，本次复核见 spec §1.2）。因此本单元的等价判据不是「与 Python 逐位相同」，而是**「与按定义手算的结果相同」**。这一条决定了后面所有决策的取向：凡是让定义变得不可手算的方案，一律否决。

### 1.2 难点不在分句，在「口径必须是定义而不是实现」

中文分句本身只有十几行逻辑。真正的风险是三处**只能靠文字钉死的口径**，它们没有上游实现可以照抄：

| 口径 | 一旦含糊的后果 | PRD-B 的落点 |
| --- | --- | --- |
| 哪些字符是边界 | 同一段话可以切成 1 句也可以切成 3 句，句数、均长、四档计数全部漂移 | FR-01 |
| 句内标点算不算句长、句末终止符算不算 | `你好。` 是 2 还是 3，直接决定手算复核能否成立 | FR-02 |
| 覆盖率的分子分母是「不同汉字」还是「汉字出现次数」 | 同一篇稿件的覆盖率可以差一倍以上 | FR-05、FR-06、FR-10 |

第四处不是口径而是**顺序**：`zh_uncovered_char_list` 的元素顺序。PRD-B FR-06 要求「按首次出现顺序」。这不是实现细节，因为 `Map`/`Set` 的迭代顺序在 MoonBit 里是**未定义**的（本次实测：同一字符集合、两种插入顺序，迭代顺序不同，见 1.3）。顺序若来自容器迭代，就会变成「看编译器心情」的契约。

### 1.3 一处已在案的裁决与一处本次实测

**已在案**：单元 A 的 design D-7 已裁决「一个分句器接口 + 两套规则集」，并给出理由（英文规则必须逐字节复刻，换行在英文侧**不**是边界；中文侧换行**是**边界，二者不可合并）。本单元沿用，不重新讨论。

**本次实测（决定 D-Z5 的形态）**：在 `F:/Temp/zhprobe` 下的探针工程里，对同一字符集合 `{人, 龘, 罐, 瓤}` 用两种插入顺序建 `Set[Char]` 与 `Map[Char, Int]`，迭代结果如下（原始输出）：

```console
$ moon run cmd/main --target native
order_a = 龘 人 瓤 罐
order_b = 龘 瓤 人 罐
map_a   = 人=4 龘=2 罐=1 瓤=1
map_b   = 瓤=1 罐=1 人=3 龘=2
```

`order_a` 的插入顺序是 `人人人龘龘人罐瓤`，`order_b` 是 `瓤罐人龘人龘人`；两者的集合相同而迭代顺序不同，且**都不是**插入顺序。结论：任何「按首次出现顺序输出」的字段，**不能**从 `Set`/`Map` 的迭代取顺序，必须另用一个只追加的序列记录首现。同一次探针里，用显式序列实现的首现顺序在两种输入下分别为 `人龘罐瓤` 与 `瓤罐人龘`，即严格随输入变化——这才是 FR-06 要求的语义。

### 1.4 本单元对单元 A 的两处既有事实的依赖

| 事实 | 证据 | 对本单元的含义 |
| --- | --- | --- |
| 值对象 `TextStats` 恰好 19 个字段，且**故意不含** `zh_` 字段 | `lib/types.mbt:16-36`；字段数由结构体字面量在编译期钉死（缺字段报 `E4044 Record fields … are undefined for type …`，本次探针实测） | 阶段 (ii) 的合并入口**必须**改单元 A 的类型；本单元的独立交付不能等它（D-Z3） |
| 门禁的字段索引是**封闭 19 名**，且对 20 名会主动报错 | `lib/cmd/gate/field_index.mbt:144`（`ALIGN_FIELD_COUNT = 19`）、`:374-384`（未知字段名报错）、`:423-430`（观测到的不同名数 ≠ 19 即报错） | 中文单元格**绝不能**进 `@gate_data`，否则 `--group=all` 会 EXIT=2（D-Z6） |

第二行不是推测：`lib/cmd/gate/field_index_wbtest.mbt:107-121` 的既有负例**正是**用一个叫 `zh_char_count` 的字段名来演示「第 20 个字段名是硬失败」：

```console
$ grep -n "zh_char_count" lib/cmd/gate/field_index_wbtest.mbt
110:    probe_cell("zh_char_count", @gate_data.EInt(1)),
115:      "field index: cell probe uses the unknown field zh_char_count (shape zh_char_count)",
```

也就是说，仓库里已经有一条测试把「中文字段进 L3」写成了**必须失败**的样例。本设计不是绕开它，而是让中文单元格在类型上根本进不去（D-Z6）。

## 三、关键约束

### 3.1 技术约束

| 约束 | 事实与出处 | 对设计的影响 |
| --- | --- | --- |
| 工具链版本 | `moon 0.1.20261012 (748b63c 2026-10-12)`；`moonc v0.10.15+943464bfa (2026-10-12)`（本次实测） | 结论只对这两个版本成立；升级触发复开（D-Z4 的行宽安全区、D-Z5 的容器顺序都要重测） |
| 字符串长度有两套语义 | `String::length()` 返回 **UTF-16 码元**数；`String::char_length()` 返回**码点**数（`C:/Users/Administrator/.moon/lib/core/builtin/string.mbt:45-49,62-88` 与 `:91-108`）。实测 `"a🤣人"`：`char_length=3`、`length=4`，且 `s[1]=55358` 是代理项 | 句长与「不同汉字数」必须按码点；用 `length()` 会在含增补平面字符时静默多算。登记为方言红线（spec §4.9 DR-Z1） |
| `String` 迭代按码点 | `String::iter` 显式合并代理对（`string.mbt:405-423`）；文档注明 `iter().count()` 可以不等于 `length()`（`:394-403`） | 逐字遍历用 `for ch in text`，不用下标 |
| `Char::to_int` 是唯一取码点的入口 | `C:/Users/Administrator/.moon/lib/core/builtin/intrinsics.mbt:1311`（`"%char_to_int"`） | 汉字判定按码点区间比较；实测 `龘=40856 (0x9F98)`、`人=20154`、`。=12290`、`，=65292` |
| `Map`/`Set` 迭代顺序未定义 | 本次实测见 1.3；核心库不承诺插入序（`C:/Users/Administrator/.moon/lib/core/hashmap/README.mbt.md` 描述的是 Robin Hood 探测布局，未声明迭代序） | D-Z5：顺序字段只从显式序列取 |
| 单行列上限 | 前缀 `let a : String = `（18 字符）下，字面量 65,514 字符通过；65,515 字符触发 `[E0033] Error Warning (text_segment_excceed)`，诊断范围 `1:65535-1:65536`，`-d --no-render` 下 EXIT=255（本次实测） | D-Z4：生成器按 ≤ 1,000 字符/行分块；实测 4 块 × 1,000 字符的一级字表源文件最长行 3,536 字节，`moon check -d --no-render` EXIT=0 |

| `moon.mod` 不接受 `files` 键、`moon package` 打包模块内全部非忽略文件 | 单元 A design §3.1（`Unexpected key 'files' found in moon.mod.`） | 中文生成数据必须落在模块内一个明确目录（`lib/zh/`），L1 输入留在模块外（`vendor/upstream/togscc/`） |
| 门禁的 `--group` 是封闭 `match` | 决策时该集合是 **9 值**（`all`/`count`/`variant`/`formula`/`lang`/`degenerate`/`errors`/`data`/`selfcheck`，无 `zh`），见 `git show 5de4045^:lib/cmd/gate/main.mbt:62-75`；`zh` 于本轮加入，见 §4.7.1。现状是 **10 值**（含 `zh`），见 `lib/cmd/gate/main.mbt:63-77`。未知值始终走 `gate_fail("unknown --group value: …")`，决策时实测 `--group=zh` → `gate: unknown --group value: zh`、EXIT=2 | 新增 `zh` 必须**同时**改代码与 AD §6（D-Z6） |

### 3.3 合规约束

| 数据 | 许可事实（逐字引用来源） | 技术后果 | 状态 |
| --- | --- | --- | --- |
| 常用字表（单元 B 新增） | `vendor/upstream/togscc/README` 逐字声明：上游为 npm 包 `togscc` 1.3.1（**MIT**），转写《通用规范汉字表》（教育部 2013-06-01 发布）；两级渠道（npm tarball 与 jsDelivr GitHub 镜像）逐元素比对相等（8,105 项全等） | MIT 可与本项目 MIT 共存；需在 `NOTICE` 与 README 中注明来源、表名、级次与「一级 3,500 字」的覆盖范围 | 技术后果明确；**授权口径仍需用户书面确认**（PRD-B 七、开放问题第 3 行） |

**一处必须写明的连带改动**：`tools/verify_l1.py` 的 `local_path()` 用硬编码的模式把 AD §1.2 的逻辑名映射到 `vendor/upstream/` 下的路径，未识别的名字直接 `SystemExit`。本次干跑实测：

```console
$ python -c "import sys; sys.path.insert(0,'tools'); import verify_l1; print(verify_l1.local_path('togscc `level1_3500.txt`（一级字表）'))"
SystemExit: unmapped AD logical name: 'togscc `level1_3500.txt`（一级字表）'
```

因此「在 AD §1.2 加一行 togscc 身份」与「在 `verify_l1.py` 加一条映射」**是同一次改动**；只加 AD 行会让 `python tools/verify_l1.py` 由 EXIT=0 变成抛异常。这条约束进入 D-Z4 的复开条件与 spec 的门禁登记节。

## 五、验收场景（回链 PRD-B US-XX）

本表只做「验收载体映射」，不新增验收标准。单元 B 没有 oracle（PRD-B B-06），因此载体只有三种：**手算复核**（按 PRD-B 定义人工推导后比对）、**夹具复核**（把常用字表换成小夹具，使分子分母可心算）、**门禁注入自证**（证明中文组的判等真的会红）。

| PRD 条目 | 设计层验收载体 | 具体单元格/步骤 | 判定命令 |
| --- | --- | --- | --- |
| PRD-B US-01（长句占比） | 手算复核 | FR-01～FR-04 的 8 组样本（含换行、含英文混排、含连续边界）；句长口径为「句内标点计入、句末终止符不计入」 | `moon run cmd/gate --target native --group=zh` |
| PRD-B US-02（用字负担） | 手算复核 + 夹具复核 | FR-05/FR-06/FR-10：全表夹具三例 + 「仅含 `人`」夹具一例 + 「含 `人` 与 `龘`」夹具一例 | 同上 |
| PRD-B US-03（侧栏实时） | 性能抽样 | 2,000 字中文样本连跑 100 次取中位数 ≤ 30 ms（PRD-B 性能 NFR） | `moon run cmd/gate --target native --bench`（既有计时入口，见 D-Z8） |
| PRD-B US-04（口径可复核） | 文档核对 + 手算复核 | README 中文局限章节三项声明；FR-07 阶段 (i) 字段集合；FR-08 语种无关两例 | 人工核对 + `--group=zh` |
| PRD-B US-05（退化输入） | 手算复核 | 空串 / 纯空白 / 纯标点 / 无汉字 四组，共 4 × 12 = 48 个单元格 | `moon run cmd/gate --target native --group=zh` |

单元格预算：16 个用例 × 12 个 `zh_` 字段 = 192（见 spec §4.7）。这个数字**不进** `FROZEN_FLOOR`（理由见 D-Z6）。

## 八、降级等价与数据流方向

### 8.1 降级路径

**`N/A — no degraded path`。**

理由三条：

1. **没有主路径/回退结构**。单元 A 的音节是「发音优先、断字回退」两层（design §8.1 的 FE1），中文侧**没有**这种结构：常用字命中与未命中不是「主路径 vs 回退」，而是 FR-05/FR-06 定义的**分子与分母的两个互斥分支**。命中进分子、未命中进分母且进未覆盖字清单——这是定义，不是降级。
2. **没有「差不多」的替代口径**。中文没有上游实现可对齐（PRD-B B-02/B-03），因此不存在「回退到某个近似实现」的可能；唯一的判据是按定义手算。
3. **没有「表缺失」分支**。常用字表随包内嵌（D-Z4；自 0.2.0 起随包，见 §1.1），运行期不查外部资源，所以不存在「找不到表 → 用英语表代替」这类 FE2 式分支。

唯一**接近**降级的是空输入与无汉字输入的分母为零分支（FR-05 裁决为覆盖率零值）。这是**零值语义**，不是降级：它不改变任何非退化输入的取值，登记在 spec §4.6。

### 8.2 数据流方向

**`N/A — no sensitive data flow`。**

理由（PRD-B 10.7 = 无）：

- 中文统计是纯本地计算：输入文本只在进程内参与分句与集合查询，不上传、不落盘、不做遥测、不读取用户环境。
- 本设计额外确认：D-Z4 选择「数据编译期内嵌」后，**运行期零文件读取、零网络**，随包常用字表（自 0.2.0 起随包，见 §1.1）是只读数据，不存在运行期的「数据从哪来」路径。
- 失败记录由**开发期**门禁程序产生（`_gate/failures-native-*.jsonl`，只含输入 SHA-256 与字段名，不含原文），不属于库运行时行为（PRD-B 10.7 已逐行声明）。

因此本节不画数据流图：没有跨越信任边界的数据移动。

| §1.3 L2 生成产物的身份 | 增加一行：常用字表内嵌形态（3,503 字符字面量 / 10,503 UTF-8 字节 / 4 个分块行；排序后行集合 SHA-256 `14adaa8718b938aad1ae82a19f631c0a8abdebb9c46b8949b8e6c55d98378dd2`） | 内嵌表是 L2 产物，必须可被「重跑生成器再比对」验证（A1-3） |
| §3.3 运行完整性 | 增加一句：`--group=zh` 的 192 个单元格由中文组自己统计，`floor=366` 仍只保护英文 L3 表 | 防止读者误以为中文组也要满足 366；同时明确「366 不被抬高」不是放宽 |
| §6 门禁参数契约 | 在 `--group` 封闭值表里增加一行 `--group=zh`（语义：中文 192 单元格），并把 `--inject=<n>` 的生效范围由「`selfcheck`」改为「`selfcheck`、`zh`」 | 该节的表格**就是**封闭集的定义；代码改而本节不改，正是仓库禁止的双形态漂移（AD §11.2 的裁决：文档是权威，程序是实现） |
| §8 生成产物所有权 | 增加两行：`lib/zh/` 的数据表与 `lib/gate/zh/` 的期望值表（生成器 = 模块外的 `tools/gen_data.py`，权威命令 `--check`，全量重建，禁手改） | 生成产物的禁手改规则必须集中在一处 |

**为什么不新建第二份 AD**（与单元 A design §10.4 同一论证，扩展而非推翻）：

- AD-1/AD-2/AD-3 三条承诺对本单元**同样适用**（数据身份、位模式比较、单命令门禁），再写一份会让同一承诺有两个版本。
- AD-4 是**负承诺**：字段契约的权威源是 PRD-A 10.3 与 PRD-B 10.3，仓库不另建字段契约文档。中文 12 字段的权威源就是 PRD-B 10.3；本 design 与 spec 都只引用、不复制。
- 唯一的中文特有的是「门禁多一个封闭组」，这件事的权威落点是 AD §6，扩展它即可。

**本设计对 AD 的改动不涉及任何既有行的语义变更**（DR3 的「只增不改」同样适用于 AD：`--group` 表增一行、`--inject` 作用域扩一个值，都是**增**，不是改写既有行的含义；`floor=366` 一行不变）。
